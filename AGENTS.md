# Architecture rules
- Keep Tech Repair client exchange separate from financial links: owner-issued expiring one-use pairing and a dedicated server-only credential authorize owner-scoped reads and contact-only receipt; serialize imports with stable per-binding identities, preserve local records on conflicts and require owner resolution against an unchanged snapshot. Remote verified owner/employee permissions must guard every exchange to prevent contact sharing from changing repairs or payments.
- Apply the shared semantic record-highlight treatment to list entries for consistent pointer and keyboard feedback without attaching automatic detail-opening behavior.
- Derive unsaved payment suggestions from current cost inputs unless the user overrides the amount; filling costs must never enable or insert a ledger payment automatically, preserving explicit payment confirmation and historical amounts.
- Validate protected edge-function identities with verified authenticated JWT claims using a caller-scoped anon client; renew client sessions before financial calls and retry only a local authentication rejection once, so expired sessions never require disabling authentication or replaying uncertain redemptions.
- Audit application-table mutations with server-side transactional triggers into an append-only, admin-readable activity history; store only allowlisted non-secret values and changed field names, never credentials, image URLs or configuration secrets. Identify actors from validated sessions, explicitly marking unattributed server operations instead of guessing ownership.
- Populate client lists and new-record selection from authorized repairs and owner-only standalone clients; deduplicate by normalized name/contact and prefer saved contact corrections linked by immutable source keys over latest repair contact. Copy only name, phone and email; client creation/edits must not alter historical repairs or payment snapshots.
- Share repair receipts through shared client-side PNG capture and validated SMS deep links; use native file sharing, then native text sharing or channel options, never automatic downloads. SMS opens the device composer; estimates never imply a ledger payment or fiscal invoice.
- Route all repair deletion, including bulk actions, through authenticated password verification and a server-only transactional RPC retaining owner/admin rules; revoke browser DELETE and rate-limit attempts to prevent bypass and brute force while preserving payment snapshots.
- Reuse a read-only details dialog across repair lists with explicit activation controls supporting mouse, touch and keyboard without editing the record.
- Keep actual payments in an immutable ledger separate from repair estimates; edits to a repair must not rewrite paid amounts or exported snapshots.
- Snapshot the repair phone on new payment insertion and export it as optional client_phone; never backfill existing payments or derive export contact data from mutable repairs, so retries preserve the original receipt contract.
- Route financial exports through an authenticated edge function using a server-only explicit account binding, a stable payment UUID and a verified receiver receipt; missing configuration leaves payments pending.
- Expose payment insertion through a validated security-definer RPC and payment reads through owner-only RLS; synchronization metadata and account bindings are server-write-only.
- Complete account linking only through a server-authenticated one-time code redemption; derive the source identity from the validated session and persist only a matching-currency verified remote receipt to prevent unverified destinations.
- Keep integration test payments in the immutable ledger with a partial unique owner index and a validated owner RPC; retries reuse the same stored payment and display success only with a verified receiver movement UUID.- Keep the Windows/Android packaging (`src-tauri/`, `.github/workflows/instaladores.yml`) independent of `src/`: the desktop and Android programs load this same web build unchanged, so do not delete those folders or add Tauri-only code to the web app.
