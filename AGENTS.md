# Architecture rules
- Populate new-record client selection only from already authorized repairs; deduplicate by normalized name/contact using the latest record and copy only name, phone and email, never equipment, estimates or payments.
- Share repair receipts through shared client-side PNG capture and validated SMS deep links; use native file sharing, then native text sharing or channel options, never automatic downloads. SMS opens the device composer; estimates never imply a ledger payment or fiscal invoice.
- Route all repair deletion, including bulk actions, through authenticated password verification and a server-only transactional RPC retaining owner/admin rules; revoke browser DELETE and rate-limit attempts to prevent bypass and brute force while preserving payment snapshots.
- Reuse a read-only details dialog across repair lists with explicit activation controls supporting mouse, touch and keyboard without editing the record.
- Keep actual payments in an immutable ledger separate from repair estimates; edits to a repair must not rewrite paid amounts or exported snapshots.
- Snapshot the repair phone on new payment insertion and export it as optional client_phone; never backfill existing payments or derive export contact data from mutable repairs, so retries preserve the original receipt contract.
- Route financial exports through an authenticated edge function using a server-only explicit account binding, a stable payment UUID and a verified receiver receipt; missing configuration leaves payments pending.
- Expose payment insertion through a validated security-definer RPC and payment reads through owner-only RLS; synchronization metadata and account bindings are server-write-only.
- Complete account linking only through a server-authenticated one-time code redemption; derive the source identity from the validated session and persist only a matching-currency verified remote receipt to prevent unverified destinations.
- Keep integration test payments in the immutable ledger with a partial unique owner index and a validated owner RPC; retries reuse the same stored payment and display success only with a verified receiver movement UUID.
